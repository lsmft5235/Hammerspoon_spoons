# Hammerspoon_spoons
Spoon tools for Hammerspoon.
See: https://www.hammerspoon.org/

## Spoons

### WallpaperRotator
Periodically rotates desktop wallpapers across all connected screens, picking a random image from a configurable directory (default `~/Pictures/Wallpapers`). Features include:
- Configurable rotation interval, persisted across restarts
- Smooth crossfade transitions via `hs.canvas`, using centered aspect-fill scaling
  to match macOS Fill Screen (including upscaling smaller images)
- A folder picker for choosing the wallpaper directory
- An optional on-screen countdown badge showing time until the next rotation
- Unique staging filenames to avoid stale renders when macOS reuses a wallpaper URL
- Bounded staging retention and automatic macOS BMP wallpaper-cache cleanup
- Hotkey bindings for rotating now, choosing a folder, setting the interval, and cleaning the cache

- Tested with MacOS Tahoe 26.6.2

See [Wallpaper_Rotator/Add-to-init.lua](Wallpaper_Rotator/Add-to-init.lua) for an example configuration.

#### Unique staging and retention

Every rotation copies the selected image to a fresh `stage_<UUID>.<extension>`
file in `~/.hammerspoon/.wallpaper_staging` (or your configured `stagingDir`).
Reusing A/B paths could leave macOS displaying an older image even though its
reported URL matched the updated file. Unique paths have avoided that behavior
in live diagnostic testing, including with fades restored.

Staging retention targets **50 files and 256 MiB**, pruning oldest files until
both targets are met. Set overrides after `hs.loadSpoon("WallpaperRotator")`
and before `:start()`:

```lua
spoon.WallpaperRotator.maxStagedFiles = 50
spoon.WallpaperRotator.maxStagedBytes = 256 * 1024 * 1024
```

Only recognized regular staging files are managed, including previous
`stage_diagnostic_<UUID>` and legacy `stage_a`/`stage_b` images. Unrelated files,
directories, symlinks and source images are not pruned. Current wallpapers
reported by connected screens and in-flight operations are protected. Protected
files can exceed the targets; unavailable screen references or filesystem
metadata cause pruning to be skipped with a warning.

**Inactive desktop/fullscreen Spaces and disconnected displays are not
protected.** Their old staged images may be removed. This is an intentional
trade-off for storage retention. The targets count managed staging files only,
not unrelated files or Apple's caches. Call `:cleanStaging()` for a manual pass.

#### macOS wallpaper-cache management

Automatic BMP cleanup remains **enabled by default every 10 rotations**, separate
from staging retention:

```lua
spoon.WallpaperRotator.enableCacheCleanup = true
spoon.WallpaperRotator.cleanupInterval = 10
```

No reliable active-BMP reference map was established during inspection. Cleanup
therefore retains the existing broad purge scope: BMPs under
`~/Library/Containers/com.apple.wallpaper.agent/Data/Library/Caches/com.apple.wallpaper.caches`
and BMPs matching `*/com.apple.wallpaper*/*` under `DARWIN_USER_CACHE_DIR`.
It does **not** identify orphaned files: active rendered caches may be removed
and regenerated by macOS, potentially causing visual disruption.

Cleanup waits for in-flight wallpaper application/fallbacks and fades to settle.
Overlapping requests are coalesced, and new rotations wait while cleanup runs.
The Console logs deleted and accessible remaining BMP file/byte counts; missing
locations, permission errors and task failures are reported rather than masked.
After 30 seconds a stalled task is asked to terminate; rotations remain paused
until it exits to avoid overlapping deletion work.

Manual `:cleanCache()` and the optional `clean_cache` hotkey use the same
operation, even when automatic cleanup is disabled. There is no immediate
"cleaned" alert before the asynchronous operation finishes.

These controls do **not** guarantee bounded macOS Wallpaper settings history,
non-BMP cache assets, or all Apple-managed wallpaper storage. Deleting image
files does not necessarily remove their entries in System Settings.

#### Migrating from the diagnostic mode

Deploy the updated Spoon and reload Hammerspoon. Remove assignments to the
retired `diagnosticUniqueStaging` flag; unique staging is now unconditional.
Remove the temporary `enableCacheCleanup = false` and
`enableFadeTransition = false` overrides to restore automatic cache management
and fades. These options and the retention limits are not persisted by the Spoon.
Existing diagnostic/A/B images are included in retention automatically.

For live acceptance, observe at least 30 rotations (or longer than the previous
anchor recurrence period), including at least three scheduled cache-cleanup
cycles, with fades enabled. Switch source folders and desktop/fullscreen Spaces.
Confirm no anchor returns during or after cleanup and inspect staging retention
and cache measurements. Automated tests cannot verify the pixels macOS displays.

Enable informational Console logging with:

```lua
spoon.WallpaperRotator.logger.setLogLevel("info")
```

#### Regression tests

Run from the repository root:

```sh
lua Wallpaper_Rotator/tests/staging_test.lua
/bin/sh Wallpaper_Rotator/tests/cache_cleanup_test.sh
```

The Lua tests require Lua 5.3+ and mock Hammerspoon, tasks and the filesystem; they
do not change the desktop or real staging files. If standalone Lua is unavailable,
the same tests can run using `npm exec --yes --package=fengari-node-cli -- fengari
Wallpaper_Rotator/tests/staging_test.lua`. The shell tests use disposable fixture
directories only, not the actual macOS wallpaper caches.
